Orientation checked with a red-top/blue-bottom lavfi source: top red, bottom blue with `flip_y = 1`. With the default blocking render (`BLOCK_FOR_TARGET_TIME=1`) it also plays (30.02–30.03 fps in 4 of 5 runs, one run 28.21 with 18 drops) but `mpv_render_context_render` then blocks the UI thread ≈ 27–31 ms per frame. **Gotchas for the implementer:** (1) Send `loadfile` only after `mpv_render_context_create` (i.e. from `RenderingSetup`); loading earlier fails with "No render context set" and mpv deselects the video track. (2) Slint's `get_proc_address` is only valid inside the notifier call; mpv uses it only during `mpv_render_context_create`, so passing a pointer to that closure as `get_proc_address_ctx` works. (3) `mpv_render_context_render` changed GL state: `GL_ACTIVE_TEXTURE` (TEXTURE1→TEXTURE0) and turned `GL_BLEND` off. FemtoVG 0.27 resets both at the start of each flush, so a run with no restore also passed, but the spike saves/restores program, VAO, array buffer, draw/read FBO, active texture + 2D textures on units 0–1, viewport, scissor/blend/cull/depth/stencil enables, blend func/equation, unpack alignment/row length/buffer. Keep the restore. (4) Render to the FBO bound at `BeforeRendering` (it was 0), size `window.size()` in physical pixels, `flip_y = 1`. Slint clears to the transparent background before `BeforeRendering`, so mpv must draw every Slint frame, not only on new video frames. (5) Update callback: runs on an mpv thread and must not call mpv. The spike coalesces with an `AtomicBool`, then `slint::invoke_from_event_loop` → `Weak::upgrade` → `window().request_redraw()`. With the non-blocking render, mpv asks for 42–60 redraws/s for 30 fps video, so Slint draws more often than needed. Calling `mpv_render_context_update` in the callback and only redrawing on `MPV_RENDER_UPDATE_FRAME` was not tried. (6) Free the render context in `RenderingTeardown` (GL current) before `mpv_terminate_destroy`, which blocks while a render context exists. The spike just exits the process. (7) With d3d11va-copy, redrawing the same frame gives ±1/255 differences (dither noise): harmless, but don't use exact pixel hashes to count frames. Note: CPU figures include the spike's own readbacks. Not tested: a real fullscreen 1920×1080 output, a second monitor, tearing (we can't see the screen; frame pacing came from mpv counters only). |
